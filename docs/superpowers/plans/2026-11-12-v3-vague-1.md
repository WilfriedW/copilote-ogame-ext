# Copilote OGame v3, vague 1 — qu'il arrête de mentir

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Supprimer les trois cartes qui mentent — une expédition proposée alors que le jeu est plein, une découverte proposée sans vaisseau d'exploration, un lien de construction qui laisse attendre un formulaire prérempli.

**Architecture:** Trois corrections localisées dans `app.js`, plus une lecture nouvelle dans `content.js` relayée par `background.js`. Aucune nouvelle dépendance, aucun découpage de fichier : le dépôt charge `ids.js` puis `app.js` comme des scripts classiques, et les tests les évaluent de la même façon.

**Tech Stack:** JavaScript sans build, extension Chrome manifest v3, tests Node sans framework (`node test/run.js`).

**Spec:** `docs/superpowers/specs/2026-11-12-plan-v3-design.md`

## Global Constraints

- Un fichier = un objet ; JSDoc sur chaque fonction ajoutée ; pas de bandeaux de commentaires ; commentaires en anglais pour les nouveaux blocs techniques, en français pour les notes de conception existantes (le fichier mélange les deux, suivre le voisinage).
- Les lecteurs DOM lisent seulement : aucun `click()`, aucun `dispatchEvent`, aucune écriture dans le DOM du jeu, aucun champ rempli.
- Aucune requête réseau vers les pages du jeu. Seul appel autorisé : `/api/*.xml`, cache d'au moins une heure.
- Aucune valeur d'univers codée en dur. Un compteur que le jeu publie se lit ; il ne se reconstitue pas à partir d'une règle connue.
- `APP_VERSION` (app.js:2) et `version` (manifest.json) restent égaux et sont incrémentés à la livraison. Cette vague livre la **1.25.0** ; la v3 complète visera la 3.0.0.
- Tests : `node test/run.js`. Base de référence avant toute modification : 124 vérifications passent.

## Review Focus

Cas que la spécification implique, qu'aucune tâche n'exerce autrement, et dont chacun a son test ajouté ci-dessous dans la tâche qui en porte le code.

- `S.slots.expo` absent — le joueur n'a jamais ouvert la page de flotte : le plan doit continuer à proposer des expéditions, pas se taire. *(Tâche 1, étape 6)*
- Lecture plus vieille que trois heures : les expéditions reviennent, sans que la carte prétende connaître le compte actuel. *(Tâche 1, étape 6)*
- `S.slots.expo[0]` supérieur au plafond — le jeu a changé de plafond entre deux lectures : aucun compte négatif, aucune boucle. *(Tâche 1, étape 6)*
- Compteur de découverte lu à zéro alors que la carte est déjà affichée : elle disparaît sans casser le rendu. *(Tâche 2, étape 7)*
- Planète sans `gid` — jamais nommée par le jeu : `goUrl` renvoie `null`, et la carte de construction affiche quand même sa note. *(Tâche 3, étape 5)*

### Task 1: Les expéditions en vol se comptent sur le chiffre du jeu

### Task 2: Le compteur de vaisseaux d'exploration

Le copilote n'envoie pas les missions de découverte : il ouvre la Galaxie, le joueur clique. Quand il ne reste aucun vaisseau d'exploration, le jeu répond « Réussite — Vaisseau d'exploration envoyé (0) » et rien ne part. Le panneau n'affiche ce compteur nulle part. Il est **lu**, jamais reconstitué à partir du « départ 50, +50 par jour » : une valeur d'univers calculée dans notre coin remplacerait un mensonge par un autre.

**Files:**
- Modify: `content.js` — à côté de la lecture des artefacts (`content.js:140-141`), et dans l'objet renvoyé (`content.js:178`).
- Modify: `background.js:128` — même garde que `s.artefacts`.
- Modify: `app.js` — `applyGame` (app.js:2338) ; la carte `discovery` (app.js:1482).
- Test: `test/run.js`

**Interfaces:**
- Consomme : l'objet publié par `content.js`, relayé dans `applyGame(g)`.
- Produit : `S.discovery` → `{left: number, at: number} | null`.

- [ ] **Step 1: Relever le libellé réel sur la page du jeu**

Le lecteur des artefacts fonctionne par expression régulière sur le texte de la page, sans sélecteur (`content.js:140`). Le compteur de découvertes se lit de la même façon, mais son libellé exact doit être relevé sur la page avant d'écrire l'expression : ouvrir la page des formes de vie ou la Galaxie et noter la phrase qui porte le nombre. **Cette étape bloque les suivantes** ; sans le libellé, l'expression serait une devinette, et une devinette qui rate laisse le compteur à `null`, ce qui est le comportement sûr mais ne livre rien.

### Task 3: Le lien de construction dit ce qu'il fait

OGame n'accepte des paramètres d'URL que sur `fleetdispatch` — c'est ce dont sa propre page Galaxie a besoin. Il n'existe aucun équivalent pour « monte Métal 21 ». `actGo` renvoie donc une simple URL de page pour un bâtiment, une recherche ou une case de forme de vie (app.js:199-205), et la carte laisse attendre un préremplissage qui ne viendra jamais. C'est une limite du jeu, à assumer à voix haute.

**Files:**
- Modify: `app.js` — nouvelle fonction après `goAttr` (app.js:214) ; `actHtml` (app.js:1295-1301).
- Test: `test/run.js`

**Interfaces:**
- Consomme : `fleetUrl(a)` (app.js:187), `actGo(a)` (app.js:197).
- Produit : `goNote(a)` → `string` (le texte de la note, ou `''`).

- [ ] **Step 1: Ajouter `goNote` et `actHtml` à la liste des symboles exportés du harnais**

- [ ] **Step 2: Write the failing test**

Sinon renvoie la phrase, une seule, en français, du même ton que les autres notes de carte : elle dit que le lien ouvre la bonne page sur la bonne planète et qu'OGame ne permet pas de pré-remplir un bâtiment.
